{%- comment -%} The ways-in tabset (plan D2, applies M12/S2/P3): the app ways (Explorer, db-query — tools you OPEN, so they are buttons, the first solid the rest ghost) then ONE shared tabset over the code routes, in the fixed order erddap · parquet · r · python · json, one panel per group PRESENT. A single group renders no tab row — the one panel shows with nothing to switch. No `data-url-tab`: assets/tabs.js's `?tab=` memory belongs to the page's FIRST tabset that carries that attribute only (R1's gate), and a page can carry this tabset alongside another (R3's methods tabset) that does own the URL. `group` rides on each way once R3/R5's plugins compute it (`page.ways[].group`). Until then this include derives it from `w.name` — today's `ways()` (_plugins/measurements.rb) names: "Explorer" / "Explorer · …" / "db-query" -> app (button, not a tab) "ERDDAP · …" -> erddap "Parquet" -> parquet "R" -> r "Python" -> python "…JSON…" (a future "this page as data" way) -> json A way whose name matches none of these and carries no explicit `group` is dropped rather than guessed into the wrong tab. Each row is the mockup's `.way`: name + about on one line, the URL on its own mono line elided from the middle by `text-overflow` (style.css), with a copy button on `assets/copy.js`'s `data-copy` contract (class `cc-copy`, icon `#i-copy` from icons_round2.html). A `code` way (R, Python, Parquet) renders a `
` instead of a URL line.
